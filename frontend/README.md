# Legal Chat

Legal Chat is a local-first Flutter interface for organizing legal conversations. The current build stores prompts and chat organization on this device, encrypted with AES-GCM. It does not include an AI model, account service, network client, or cloud sync. Sending a prompt saves it locally and shows that replies are unavailable; the app never invents assistant responses.

## Run

Install Flutter and enable the platform you want, then run these commands from `frontend/`:

```sh
flutter pub get
flutter run -d windows
flutter run -d linux
flutter run -d macos
flutter devices
flutter run -d <physical-phone-device-id>
```

Windows, macOS, Linux, Android, and iOS are the five intended targets. Each needs its usual platform SDK and device/runtime; iOS and macOS builds require a Mac. The unsupported-runtime storage stub exists only so Flutter's optional web preview can render the interface; persistence is supported on the five native targets. A future embedded backend can implement `ChatBackend` and be passed to `ChatController`; the current `UnconfiguredBackend` is explicit and safe.

See [platform setup](docs/SETUP.md) for the installed SDK locations, physical-phone instructions, Windows Developer Mode/C++ requirements, Linux keyring prerequisites, and Apple signing requirements. See [verification](docs/VERIFICATION.md) for what has actually been tested.

## What was built

- Gemini-inspired responsive sidebar/drawer and chat composer, with light, dark, and system themes.
- Persistent local chats: create, rename, pin/unpin, delete with confirmation, and group into named projects. Deleting a project preserves its chats.
- Prompt saving, Markdown/code response rendering, copy-response action, and backend-ready stop/regenerate behavior. No model is bundled, so real answers are unavailable.
- Authenticated local encryption with the random key stored by the operating system. No account or internet connection is needed for local organization.
- Tiempos Text for generated text, Styrene B Bold for the composer/headlines, and Fougie for interface text.

The app is named **Legal Chat**; its source folder is simply `frontend`. All repository changes for this work are contained here. Flutter and Android tooling were installed outside the repository with permission.

## Source map

- `lib/main.dart` builds the responsive sidebar, chat view, composer, theme picker, and honest unavailable states.
- `lib/models.dart` defines serializable workspace, project, chat, and message data.
- `lib/backend.dart` defines the stream/cancel generation contract and the no-model implementation.
- `lib/chat_controller.dart` owns local chat/project actions and routes generation through the backend contract.
- `lib/secure_store.dart` encrypts the workspace with AES-GCM and keeps the random key in the platform secure-storage plugin. Loading errors lock the workspace so damaged history cannot be overwritten; there is no plaintext fallback.
- `lib/blob_storage.dart` defines the local blob contract; `lib/storage_blob_io.dart` stores the encrypted envelope with temp/backup replacement on native platforms.
- `lib/storage_blob_stub.dart` fails explicitly on unsupported runtimes such as the optional web preview.
- `test/models_test.dart` checks workspace serialization.
- `test/controller_test.dart` checks prompt persistence and chat/project actions with memory storage and a fake backend.
- `test/secure_store_test.dart` checks encrypted persistence and tamper rejection.
- `test/storage_blob_io_test.dart` checks interrupted-save recovery and atomic replacement on native platforms.
- `test/responsive_test.dart` checks the narrow-screen drawer and wide-screen sidebar layouts.
- `pubspec.yaml` declares Flutter, Markdown rendering, filesystem location, secure key storage, crypto, and the supplied font assets.
- `analysis_options.yaml` enables Flutter's standard lint set.

Flutter platform folders (`android/`, `ios/`, `linux/`, `macos/`, `windows/`) are generated by `flutter create`. They hold platform manifests, launchers, and native plugin registration. Android backup must exclude the secure-storage key; a restored encrypted file without its device key cannot be decrypted.

The complete [file inventory](FILES.md) lists every added version-controlled file and its purpose, including native runners, generated assets, tests, and documentation. Build caches, local SDK paths, IDE files, and local conversation data are excluded by this folder's own `.gitignore`.

## Replacing the model backend

Read [backend and sync integration](docs/BACKEND_AND_SYNC.md) for the exact files and steps. Implement `ChatBackend` in a new isolated runtime adapter, then replace `UnconfiguredBackend()` in `lib/main.dart`. No UI-to-Ollama dependency exists to remove. The embedded runtime and model weights will be selected when the model files and test device are supplied.

The approved dependency set is Flutter, `flutter_markdown_plus` (maintained Markdown renderer), `path_provider`, `flutter_secure_storage`, and `cryptography`. `pubspec.lock` fixes the resolved app dependencies. Encryption uses a standard package rather than a custom cipher.

## Current limits and future sync

General Chat is the only available mode. Family, Criminal, and the combined Jev / Laya mode are unavailable until separately implemented. Messages can preserve attachment references (local path, display name, and media type) for a future provider, but the current interface has no file picker, attachment parser, or attachment upload. Login, account management, model selection, cloud synchronization, and share-link creation are unavailable. The Share dialog explains future choices: a response, whole chat, or project; read-only access or an independent continuation; and resharing permissions. It creates no link.

Cloud sync should remain optional and require an account. Future settings should distinguish downloading a synced copy and removing only this device's local copy from deleting the shared item globally. Global deletion needs a server tombstone so a later sync cannot restore it. Deleting an item that was never synced should simply delete the local item. Independent shared continuations should become forks with their own history and explicit permissions, rather than edits to the original. This app deliberately has no speculative sync framework today.

The supplied fonts are `TiemposText-Regular.ttf` (regular), `Styrene-B-Bold-Regular.ttf` (bold), and `Fougie.ttf` (regular), under `assets/fonts/`. The user confirmed these fonts are licensed for this app; license documents were not included in the asset folder.
